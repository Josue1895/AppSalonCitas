# Repositorios

## Repositorio y control de versiones — AppSalonCitas

### 1. Introducción

El proyecto AppSalonCitas utiliza Git y GitHub como herramientas de control de versiones y colaboración.

El repositorio permite almacenar el código fuente, realizar seguimiento de los cambios, organizar el trabajo de los integrantes y mantener una versión principal del proyecto.

### 3. Organización del repositorio

El proyecto está organizado en diferentes directorios:

| Directorio              | Responsabilidad                                  |
| ----------------------- | ------------------------------------------------ |
| `app/`                  | Lógica principal de la aplicación.               |
| `app/Http/Controllers/` | Controladores backend.                           |
| `app/Http/Middleware/`  | Middleware de seguridad y acceso.                |
| `app/Http/Requests/`    | Validación de solicitudes.                       |
| `app/Models/`           | Modelos de datos.                                |
| `app/Exports/`          | Clases para exportación de información.          |
| `database/migrations/`  | Estructura y modificaciones de la base de datos. |
| `database/seeders/`     | Datos iniciales.                                 |
| `resources/views/`      | Interfaces Blade.                                |
| `resources/css/`        | Hojas de estilo.                                 |
| `resources/js/`         | Código JavaScript.                               |
| `routes/`               | Definición de rutas.                             |
| `tests/`                | Pruebas automatizadas.                           |

### 4. Ramas del repositorio

Durante el desarrollo se identificaron cuatro ramas de trabajo:

#### Rama main

**Nombre:** `main`

Es la rama principal del repositorio y sirve como referencia para la versión central del proyecto.

En el ZIP analizado, esta es la única rama local y remota disponible.

#### Rama josue/frontend

**Nombre:** `josue/frontend`

Rama asociada al trabajo de frontend.

Su denominación indica que está destinada al desarrollo de la interfaz y los componentes visuales del sistema.

#### Rama jaider/backend

**Nombre:** `jaider/backend`

Rama asociada al trabajo de backend.

Su denominación indica que está destinada al desarrollo de la lógica del servidor y las funcionalidades internas.

#### Rama kevin/pruebas

**Nombre:** `kevin/pruebas`

Rama asociada al trabajo de pruebas.

Su denominación indica que está destinada a las actividades de verificación y pruebas del proyecto.

**Nota:** Los roles anteriores se describen a partir de los nombres de las ramas. No se dispone de los commits individuales de esas ramas para verificar qué archivos o funcionalidades fueron desarrollados en cada una.

### 5. Organización del trabajo colaborativo

El uso de ramas permite separar las actividades de desarrollo y reducir conflictos entre los cambios realizados por diferentes integrantes.

La organización identificada es:

| Rama             | Área de trabajo        |
| ---------------- | ---------------------- |
| `main`           | Integración principal. |
| `josue/frontend` | Desarrollo frontend.   |
| `jaider/backend` | Desarrollo backend.    |
| `kevin/pruebas`  | Pruebas del sistema.   |
